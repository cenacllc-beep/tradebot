# Incident 2026-11-06: Kalshi settled a rain market "scalar", and the bot only knew yes and no

Status: fixed in release r79 (deployed 2026-11-07, before the first real-money orders on Nov 11). No paper trade, no
limit order and no live order sat on an affected market, so nothing was lost or misreported.

## 1. What happened
- At 2026-11-06 20:36 UTC Kalshi finalized **KXRAIN-26OCT30-PHX** (Phoenix rain, Oct 30). Its result is `"scalar"`, not
  yes or no: a YES contract paid $0.99 and a NO contract $0.01. The facts below come from Kalshi's live API, read by the
  bot's own `kalshi.get` on the PC:
  - status `finalized`;
  - result `scalar`;
  - `settlement_value_dollars` `0.9900`;
  - `expiration_value` empty.
- Three later Phoenix markets, **KXRAIN-26NOV03-PHX**, **-26NOV04-PHX** and **-26NOV05-PHX**, are still `closed` with no
  result. Nov 3's and Nov 4's are past their `latest_expiration_time`. Phoenix's daily climate report (CLIPHX) looks
  unavailable to Kalshi for these days. All four are in the gate's log for test days. The bot holds no paper trade,
  limit order or live order on any of them (checked in paper.db and live.db).
- Every settle since then has printed `SETTLE WARNING: KXRAIN-26OCT30-PHX is finalized with result 'scalar'; its paper
  trade stays open`. The 20:55 evening run printed it too. It came from the gate's market log (obs). No trade was on
  the market.

## 2. What the code did (before the fix)
Kalshi's settlements API lists four results for a binary market: `yes`, `no`, `scalar` and `void`. `void` means
"all positions returned at original cost". The bot understood only two of them:

| Part | Before | Effect of a scalar or void result |
|---|---|---|
| strategy.settle (paper trades) | `if r in ("yes","no")` | The trade stays `open` for good. Its cost and fee keep using room under the 15% exposure cap ($3.75) and cash. Its loss never reaches the 10% daily loss stop. The gate look waits for it until LOOK_DEADLINE. |
| strategy.settle (gate's market log, obs) | the same | The market stays unresolved. Correct: the gate's Brier score needs a yes/no outcome. Handled since today by LOOK_DEADLINE (Nov 18). |
| shadow.settle (limit-order ledger) | the same | The same as paper trades, on its own $25. |
| live.sync (real orders) | the same | The order stays open in live.db for good. `local_at_risk` keeps counting its cost, so less room for new orders. That is the safe direction. Its loss never reaches the $2.50 daily loss stop or the 25% drawdown pause, which is the unsafe direction. |
| account_view (the paper account page) | settled only if yes/no | A settled scalar trade would show as still open, valued at cost. |

**Root cause.** The settlement code assumed a binary market has exactly two final outcomes. That assumption sits in
three copies of the same `if r in ("yes","no")` test (paper, limit-order ledger, live). Each treats anything else as
"not decided yet". Kalshi's market model has two more final outcomes. So a final scalar or void result looks the same
as "still waiting", forever. The old warning described the symptom ("check it by hand") but nothing acted on it.

**Why it matters now.** From Nov 11, live.py copies v3's paper bets to real money (the user's decision of 2026-11-06).
A real order on a market that settles scalar or void would have stayed open in live.db. A loss there would have been
invisible to the daily loss stop and the drawdown pause, the two automatic brakes besides the $25 cap.

## 3. The fix
One rule, in strategy.py, used by all three ledgers:
- `settle_value(m)`: the dollars a YES contract pays in a scalar settlement. It reads `settlement_value_dollars`, else
  the older `settlement_value` in cents. It returns None unless the value is a number from 0 to 1, so NaN, infinity,
  text and out-of-range values all give None.
- `payout(m, side)` gives `(result, dollars a contract)`, or None while the market cannot be settled:
  - `yes`/`no`: as soon as Kalshi reports them, exactly as before;
  - `scalar`: only once the market is `finalized` (or `settled`), and only with a usable value. YES pays the value and
    NO pays 1 - value;
  - `void`: only once final.
- `settled_pnl(...)`:
  - yes/no: the old formula, to the bit;
  - scalar: n × payout - cost - fee;
  - void: -fee. The cost comes back; the fee is assumed kept because Kalshi's docs do not say it is refunded. That
    errs toward a slightly worse number.
- `market_of(t)`: the retrying lookup now returns Kalshi's whole market, because the settlement value is needed.
  `result_of` still returns the result string. It warns only when a final market still cannot be settled (for example
  scalar with no value).
- The users of the rule:
  - strategy.settle;
  - shadow.settle;
  - live.sync, which also prints a line when Kalshi reports a result it cannot settle yet;
  - dashboard.won and account_view, which show a scalar or void trade as won or lost by its P&L and close it with what
    it paid.
- **Unchanged on purpose:**
  - The gate's market log keeps yes/no only.
  - audit.record_result keeps the ledger's market results yes/no.
  - research/nov11.py, plan7.py and plan8.py are pre-registered and untouched; no test-day trade is on such a market.
  - Every lock and limit in live.py.

## 4. Edge cases
| Case | Behaviour now |
|---|---|
| scalar while `determined` (not final) | Waits: the value can still change |
| scalar `finalized` with no value or an unreadable one | Stays open, with a warning at each settle and sync, for a person to check on Kalshi |
| scalar value exactly 0 or 1 | Settles: it is a valid value |
| void | Settles at -fee (assumed). Check the real refund on Kalshi's settlement record if one ever happens with real money |
| yes/no later `disputed` or `amended` | **Not handled, as before:** the first yes/no is recorded and never revised. The ledger's market results print a warning if a later settle sees a different result. Rare; left as it was so the gate's data does not change before its look |
| `closed` past its expiration with no result (Phoenix Nov 3) | Waits, correctly. An open trade on it would keep holding cap room until Kalshi decides |
| market missing (HTTP 404) in live.sync | Skipped, as before |
| fractional fill counts | n × payout works on fractions |
| never-binary markets in the gate's log | Looked up again at every settle (one request each); harmless at today's numbers |
| win counts in learn.py, metrics, postmortem, control_view, report() and the Nov 11 report | Count scalar and void as not won; their P&L is exact. Accepted: rare, and the pre-registered report must not change |

## 5. Proof
- tests/test_settle.py section 8 covers:
  - every result and status combination of payout();
  - bit-for-bit yes/no P&L;
  - paper settles of scalar (both sides), void, not-final and missing-value markets in one run;
  - the gate's log staying yes/no;
  - room under the cap freed;
  - the account view.
- tests/test_live.py section 8 runs live.sync against the fake exchange:
  - a scalar order first without a value (left open, warned), then with one: P&L recorded, at-risk reduced, daily P&L
    includes it;
  - a void order: P&L = -fee.
- Full suite: 41 tests pass.
- PLAN8's frozen identity (forecast code and PLAN7's reused functions) is identical before and after.
